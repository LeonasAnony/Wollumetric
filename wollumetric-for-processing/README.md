# Wollumetric for Processing

## Intro

This library renders 3D Processing scenes on a Wollumetric wiremap display.

**Requires Processing 4.x** (Java 17+, OpenGL 3.2+).
[Processing](https://processing.org/) is a simplified Java environment for creative coders.

## Usage

If you are writing a 3d Processing sketch, and have this:

```
void setup() {
  size(1920, 1200, P3D);
}

void draw() {
  sphere(60);
}
```

You can make some minor adjustments to render it in a Wollumetric display:

```
import lumarca.*;
public Wollumetric thisWollumetric;

void setup() {
  size(1920, 1200, Wollumetric.RENDERER);
  thisWollumetric = new Wollumetric("wollumetricConfig.json", this);
}

void draw() {
  sphere(60);
}
```

## Config File

The config is a JSON file in the sketch's `data/` folder:

```json
{
  "version": "2.0.0",
  "wiremapFile": "optimized-32x20-1.6-94_strings.txt",
  "structureWidth": 32,
  "structureDepth": 20,
  "throwRatio": 1.6,
  "margin": 0
}
```

**wiremapFile** is the path to a wiremap text file (in the `data/` folder). Each line contains `angle x z height` separated by whitespace. These files are generated by the Wollumetric py-scripts.

**structureWidth** is the physical width of the display at the near (projector-facing) plane, in real units\*.

**structureDepth** is the physical depth of the display, in real units\*.

**throwRatio** is the projector's throw ratio (projection distance / image width).

**margin** is the number of black pixels between each column of pixels. Use 0 for no margin.

**mapCache** is used internally for caching the map texture. Delete this key (or the corresponding `.png` file) to force map regeneration after changing the wiremap or config.

\*Real units can be centimeters, inches, etc. — stay consistent.

## Wiremap File Format

Each line in the wiremap text file describes one vertical string:

```
angle  x  z  height
```

- **angle**: horizontal angle from projector center (radians)
- **x**: world-space X position of the string
- **z**: world-space Z depth (0 = near plane, max = far plane)
- **height**: projected height of the string

These files are generated by the Wollumetric `py-scripts/createPoints.py` → `createStrings.py` → `strings2txt.py` pipeline.

## What Processing Features are supported?

Processing features that aren't graphics-related are fully supported. This includes things like mouse, key, data manipulation, string handling, sound, etc...

Some graphics functions are supported. The following will work as you might expect:

- sphere()
- box()
- all matrix transforms (translate, scale, rotate, etc)
- fill(), including alpha support
- background()

The following are not supported and will not be built into this library as they aren't really relevant to volumetric rendering:

- textures
- lighting
- camera

## Features to build

- custom shaders to create your own volumetric effects
- additional primitives via new distance function shaders
- live 3D data streams (e.g. from TouchDesigner via OSC)
- 3D model loading (e.g. STL → signed distance field)
- stroke and all stroke functions (color, weight) for drawing surface pixels of geometries
- convenience methods for orientation, origin, and unit definitions
- decouple the initializer from the renderer so that you can have a Wollumetric object while still using P3D

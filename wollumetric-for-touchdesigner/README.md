# Wollumetric for TouchDesigner

Renders any SOP geometry onto a Wollumetric wiremap display.  Three
pipeline options are provided:

| Pipeline | Speed | Dependencies | Geometry types |
|----------|-------|-------------|----------------|
| **Direct** (recommended) | Real-time | numpy only | Closed polygon meshes (exact, no voxelisation) |
| **GPU** | Real-time | numpy only | Polygonal meshes (voxelised) |
| **CPU** (fallback) | Slower | numpy + scipy | Meshes, lines, point clouds (voxelised) |

Per-vertex colour via the `Cd` attribute (white if absent).  Multiple
objects with individual colours are supported.

---

## Prerequisites

| What | Where |
|---|---|
| `_strings.txt` wiremap file | Generated by `py-scripts/createStrings.py` + `strings2txt.py` |
| Map texture PNG | Generated by `py-scripts/createMapTexture.py` |
| Volume size values | Printed by `createMapTexture.py` at the end (`uVolumeSize = (x, y, z)`) |
| **scipy** *(CPU pipeline only)* | `python -m pip install scipy` in TD's Python (see below) |

Run `createMapTexture.py` before setting up the TD network:

```
python py-scripts/createMapTexture.py wiremaps/radius-480-48x30-2.2-170.0_strings.txt
```

It will ask for screen resolution (projector native res, e.g. `1920 × 1200`)
and print the volume size you'll need later.

## GPU Pipeline — Network Setup

The GPU pipeline uses a lightweight **Script TOP** to extract triangle
data and a **GLSL TOP** to perform scanline even-odd voxelisation
entirely on the GPU.  No scipy required.

```
 ┌──────────────────┐
 │  file_in_top     │  File In TOP — map texture PNG
 │  (map_texture)   │
 └────────┬─────────┘
          │ input 0
          ▼
 ┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
 │  glsl_top        │◄────│  glsl_top        │◄────│  script_top      │
 │  (renderer)      │  1  │  (gpu_voxelizer) │  0  │  (tri_data)      │
 └────────┬─────────┘     └──────────────────┘     └────────▲─────────┘
          │                                                 │
          ▼                                          ┌──────┴─────────┐
 ┌──────────────────┐                                │  [your SOP]     │
 │  null_top        │                                │  sphere / torus  │
 │  (output)        │                                │  / file_in / ... │
 └────────┬─────────┘                                └─────────────────┘
          │
          ▼
 ┌──────────────────┐
 │  window_comp     │  Window COMP — projector output
 └──────────────────┘
```

### Step-by-step

#### 1. File In TOP  (`map_texture`)

| Parameter | Value |
|---|---|
| File | Path to your `*_map_1920x1200.png` |

The resolution of this TOP determines the projector output resolution.

#### 2. Scene SOP chain

Build any SOP network you like.  The final SOP **must** be positioned
inside the Wollumetric volume coordinate space (see *Volume Coordinate
System* below).

To add colour, insert a **Point SOP** or **Color SOP** before the end to
give your geometry a `Cd` point attribute.

#### 3. Script TOP  (`tri_data`)

1. Create a **Text DAT** (e.g. `gpu_voxelizer_script`).
2. Paste the contents of `wollumetric_gpu_voxelizer.py` into it.
3. Create a **Script TOP**.
4. On the Script TOP's **Script** page, set **Callbacks DAT** →
   `gpu_voxelizer_script`.
5. Click **Setup Parameters** at the bottom of the Script TOP's
   parameter pane.
6. Set the custom parameters:

| Parameter | Value |
|---|---|
| **SOP Path** | OP path to your scene SOP, e.g. `/project1/geo1/torus1` |
| **Voxel Resolution** | `64` (increase for detail, decrease for speed) |

#### 4. GLSL TOP  (`gpu_voxelizer`)

1. Create a **GLSL TOP**.
2. On the **GLSL** page:
   - Set **Pixel Shader** (or **Pixel DAT**) to a **Text DAT** containing
     the contents of `wollumetric_gpu_voxelizer.glsl`.
   - Set **Num Color Buffers** to `1`.
3. Wire **input 0** ← `tri_data` (Script TOP).
4. On the **Common** page:
   - Set **Output Resolution** to use expressions:
     - Width: `int(op('tri_data').par.Atlaswidthout)`
     - Height: `int(op('tri_data').par.Atlasheightout)`
   - Set **Pixel Format** to `32-bit float (RGBA)` for best precision.
   - Set **Input Smoothness** for all inputs to **Nearest**.
5. Configure uniforms on the **Vectors** pages (see *GPU Voxelizer
   Uniforms* below).

#### 5. GLSL TOP  (`renderer`)

1. Create a **GLSL TOP**.
2. Set **Output Resolution** to match the projector (e.g. 1920 × 1200).
3. On the **GLSL** page:
   - Set **Pixel Shader** (or **Pixel DAT**) to a **Text DAT** containing
     the contents of `wollumetric_render.glsl`.
   - Set **Num Color Buffers** to `1`.
4. Wire **input 0** ← `map_texture` (File In TOP).
5. Wire **input 1** ← `gpu_voxelizer` (GLSL TOP).
6. On the **Common** page, set **Input Smoothness** for all inputs to
   **Nearest** (avoids sub-pixel colour bleeding in the atlas).
7. Configure uniforms on the **Vectors** pages (see *Renderer Uniforms —
   GPU Pipeline* below).

#### 6. Null TOP  (`output`)

Wire from the renderer GLSL TOP.  Connect to a **Window COMP** set to
your projector display.

## GPU Voxelizer Uniforms

All uniforms are `vec4`.  Set them on the `gpu_voxelizer` GLSL TOP's
**Vectors** parameter page.

| Slot | Uniform Name | value …x | value …y | value …z | value …w |
|:----:|:-------------|:---------|:---------|:---------|:---------|
| 0 | `uVoxelParams` | `op('tri_data').par.Voxelresout` | `op('tri_data').par.Slicesperrowout` | `op('tri_data').par.Atlaswidthout` | `op('tri_data').par.Atlasheightout` |
| 1 | `uMeshMin` | `op('tri_data').par.Meshminxout` | `op('tri_data').par.Meshminyout` | `op('tri_data').par.Meshminzout` | `0` |
| 2 | `uMeshMax` | `op('tri_data').par.Meshmaxxout` | `op('tri_data').par.Meshmaxyout` | `op('tri_data').par.Meshmaxzout` | `0` |
| 3 | `uTriParams` | `op('tri_data').par.Numtrianglesout` | `0` | `0` | `0` |

Replace `'tri_data'` with the actual operator name of your Script TOP
if you renamed it.

## CPU Pipeline — Network Setup (Fallback)

The CPU pipeline uses a single **Script TOP** that performs voxelisation
in Python (numpy + scipy).  It supports polygonal meshes, line geometry,
and point clouds, but is slower than the GPU pipeline.

Use this when you need line or point-cloud voxelisation, or if the GPU
pipeline is unavailable.

```
 ┌──────────────────┐
 │  file_in_top     │  File In TOP — map texture PNG
 │  (map_texture)   │
 └────────┬─────────┘
          │ input 0
          ▼
 ┌──────────────────┐     ┌──────────────────┐
 │  glsl_top        │◄────│  script_top      │  Script TOP — CPU voxeliser
 │  (renderer)      │  1  │  (voxelizer)     │
 └────────┬─────────┘     └────────▲─────────┘
          │                        │
          ▼                 ┌──────┴─────────┐
 ┌──────────────────┐      │  [your SOP]     │  Any SOP chain
 │  null_top        │      │  sphere / torus  │
 │  (output)        │      │  / file_in / ... │
 └────────┬─────────┘      └─────────────────┘
          │
          ▼
 ┌──────────────────┐
 │  window_comp     │  Window COMP — projector output
 └──────────────────┘
```

## Volume Coordinate System

The map texture encodes positions in a coordinate space that spans:

```
X :  0  →  sizeX       (horizontal, centred at sizeX/2)
Y :  0  →  sizeY       (vertical, 0 = bottom)
Z :  0  →  sizeZ       (depth, 0 = near / projector side)
```

Your scene SOP geometry must be **positioned within these bounds** for
it to appear on the display.

### Practical tips

- Create a **Box SOP** with size `(sizeX, sizeY, sizeZ)` centred at
  `(sizeX/2, sizeY/2, sizeZ/2)` to preview the volume.
- Use **Transform SOPs** to move/rotate your scene inside the volume.
- Objects partially outside the volume are clipped at the boundary.

## Direct Pipeline — Network Setup (GPU, Exact)

The direct pipeline performs ray‑casting entirely on the GPU, giving
an exact, deterministic result with zero voxelisation artefacts and
real‑time performance.  It reuses the triangle‑data Script TOP from
the GPU pipeline (`wollumetric_gpu_voxelizer.py`) and adds a single
GLSL shader (`wollumetric_direct_render.glsl`) that reads the map
texture, ray‑casts each pixel against the triangle data, and outputs
the final projector image in one pass.

```
 ┌──────────────────┐
 │  file_in_top     │  File In TOP — map texture PNG
 │  (map_texture)   │
 └────────┬─────────┘
          │ input 0
          ▼
 ┌──────────────────┐     ┌──────────────────┐
 │  glsl_top        │◄────│  script_top      │  Triangle data
 │  (direct_render) │  1  │  (tri_data)      │
 └────────┬─────────┘     └────────▲─────────┘
          │                        │
          ▼                 ┌──────┴─────────┐
 ┌──────────────────┐      │  [your SOP]     │
 │  null_top        │      │  sphere / torus  │
 │  (output)        │      │  / file_in / ... │
 └────────┬─────────┘      └─────────────────┘
          │
          ▼
 ┌──────────────────┐
 │  window_comp     │  Window COMP — projector output
 └──────────────────┘
```

### Direct pipeline step-by-step

#### 1. File In TOP  (`map_texture`)

| File | Path to your `*_map_1920x1200.png` |

Same as the other pipelines.

Build any SOP network.  The final SOP **must**:
- Be positioned inside the Wollumetric volume coordinate space
- Have a `Cd` point attribute (add via **Point SOP** or **Color SOP**)
- Be a **closed (watertight) polygon mesh**

#### 3. Script TOP  (`tri_data`)

2. Paste the contents of `wollumetric_gpu_voxelizer.py` into it.

   `gpu_voxelizer_script`.
5. Click **Setup Parameters**.
6. Set the custom parameters:

| Parameter | Value |
|---|---|
| **SOP Path** | OP path to your scene SOP, e.g. `/project1/geo1/torus1` |
| **Voxel Resolution** | Any value (not used by the direct renderer, but required by the Script TOP) |

#### 4. GLSL TOP  (`direct_render`)

1. Create a **GLSL TOP**.
2. Set **Output Resolution** to match the projector (e.g. 1920 × 1200).
3. On the **GLSL** page:
   - Set **Pixel Shader** (or **Pixel DAT**) to a **Text DAT** containing
     the contents of `wollumetric_direct_render.glsl`.

4. Wire **input 0** ← `map_texture` (File In TOP).

6. On the **Common** page, set **Input Smoothness** for all inputs to

7. Configure uniforms on the **Vectors** pages (see below).

#### 5. Null TOP → Window COMP

Wire from the GLSL TOP to a Null TOP, then to a **Window COMP** set
to your projector display.

## Multi-Object Setup

### Option A — Merge SOP (simplest)

1. Give each SOP its own colour using a **Point SOP** → set `Cd`.
2. Use a **Merge SOP** to combine all geometry into one stream.
3. Feed the merged SOP into a single voxeliser chain.

Vertex colours are preserved per-object.  For overlapping geometry, the
last voxel write wins (order depends on triangle iteration).

### Option B — Duplicate pipeline (full control)

For independent control over colour, resolution, and compositing:

1. Create one voxeliser chain per SOP.
2. All renderer GLSL TOPs share the same **File In TOP** (map texture)
   as input 0.
3. Combine all renderer outputs with a **Composite TOP** (operation:
   **Add** or **Over**).

This allows per-layer resolution, fill colour, and independent
enable/disable, but is slower due to multiple voxelisation passes.

## Performance Tips

- **GPU pipeline**: The GLSL voxeliser runs in real-time for typical
  meshes (< 10 000 triangles).  The Script TOP only re-cooks when
  the SOP or resolution parameter changes.
- **Animated geometry**: Keep resolution at 32–64 for interactive
  rates.  The GPU pipeline handles this much better than the CPU one.
- **Complex meshes**: Reduce polygon count with a **Polyreduce SOP**
  before voxelising.  At low voxel resolutions, high polygon counts
  create redundant work.
- **Triangle count limit (GPU)**: The triangle data texture stores one
  column per triangle.  With a max texture width of 16 384, meshes
  above ~16 000 triangles should be reduced first.
- **Multiple objects**: The Merge SOP approach (Option A) is faster than
  duplicated pipelines because it voxelises once.
- **CPU-only geometry**: If you need line or point-cloud voxelisation,
  use the CPU pipeline or convert lines/points to thin polygons first.

## Troubleshooting

**Nothing renders (black output)**
- Check that `uVolumeSize` is set to non-zero values.
- Use debug mode 1 to verify the map texture is loaded.
- Use debug mode 2/3 to verify the voxel atlas has data.
- Confirm your SOP is positioned within the volume coordinate system.
- Check the Textport (`Alt+T`) for `[wollumetric]` debug messages.

**Geometry appears in the wrong position**
- Verify the volume coordinate system: X ∈ [0, sizeX], Y ∈ [0, sizeY],
  Z ∈ [0, sizeZ].
- The volume centre is at `(sizeX/2, sizeY/2, sizeZ/2)`.
- Use a Box SOP reference to visualise the bounds.

**Blocky / low-resolution appearance**
- Increase the **Voxel Resolution** parameter on the Script TOP
  (try 96 or 128).

**GPU voxeliser atlas is blank (debug mode 3 shows nothing)**
- Verify the `uTriParams.x` uniform is non-zero (check
  `op('tri_data').par.Numtrianglesout` in the Textport).
- Verify the output resolution expressions on the voxeliser GLSL TOP
  are evaluating to non-zero values.
- Check that **Pixel Format** on the voxeliser GLSL TOP is set to
  `32-bit float (RGBA)`.
- Ensure the SOP has polygon primitives (lines and points are not
  supported by the GPU pipeline — use the CPU pipeline for those).

**Script TOP shows errors (CPU pipeline)**
- Ensure **scipy** is installed: open TD's Textport (`Alt+T`) and run
  `import scipy`.  If it fails, install from CMD with:
  `"C:/Program Files/Derivative/TouchDesigner/bin/python.exe" -m pip install scipy`
- Ensure NumPy is available (`import numpy` in the Textport).
- Double-check the **SOP Path** is valid and the SOP has geometry.

**Colours are wrong**
- Confirm the SOP has a `Cd` point attribute (inspect in a
  Geometry Viewer).  Without `Cd`, all geometry renders white.

**Performance is too slow**
- Switch from the CPU to the GPU or Direct pipeline.
- Lower voxel resolution (32–48 for real-time) in the GPU/CPU pipelines.
- Reduce polygon count with Polyreduce SOP.

**Direct pipeline: no intersection visible**
- Ensure the scene SOP overlaps the volume coordinate space.
- Verify `uTriParams.x` is non-zero (check
  `op('tri_data').par.Numtrianglesout` in the Textport).
- Make sure the scene SOP is a **closed (watertight) polygon mesh**.
  The ray‑cast even–odd test requires a watertight surface.
- Use debug mode 2 to see the inside/outside mask.
